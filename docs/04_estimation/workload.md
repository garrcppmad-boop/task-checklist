# 工数見積もり：チーム業務共有ボード

> 要件定義書（`docs/requirements.md`）の機能一覧（F-01〜F-19）と非機能要件をもとにした工数見積もり。

## 見積もりの方法（ストーリーポイント法）

【ポイント基準】
- 1ポイント = 1時間相当（目安）

【相対見積もり】

| ポイント | 難しさ | この見積もりでの例 |
|---|---|---|
| 1 | 非常に簡単（既知の作業） | ― |
| 2 | 簡単 | ログイン（Breeze の機能をそのまま使う）、自分の業務一覧（チームの一覧の条件違い） |
| 3 | 普通 | 業務の作成、キーワード検索、期限による色分け、権限管理（Policy） |
| 5 | やや複雑 | チームの業務一覧、編集・削除、画像アップロード、絞り込み、コメント |
| 8 | 複雑 | ブックマーク（Ajax）、テストコード、デプロイ |
| 13 | 非常に複雑（分割推奨） | なし（13 になるものは分割した） |

> 練習課題のユーザーストーリー（`docs/practice/userstory-practice.md`）のポイントは「機能同士の大きさの比較」に使った相対値。
> この見積もりは「1ポイント＝1時間」で、実際にかかる時間として見積もり直したもの。

## バッファについて

開発工数 98 時間に対して、**25%（25 時間）** のバッファを追加した（一般的な目安は 20〜30%）。

| バッファの使い道 | 想定 |
|---|---|
| 想定外のバグ修正 | Ajax（ブックマーク）や画像アップロードなど、初めて組み合わせる機能でのつまずき |
| 仕様変更 | ヒアリングの確認事項（他チームの業務を見られるか、削除を戻せるか、2MB を超える写真）の回答による修正 |
| レビュー・修正時間 | 講師レビューでの指摘への対応 |
| テスト・デバッグ時間 | テストで見つかった不具合の修正、スマホでの表示確認 |

- 20% にした場合：98 + 20 = 118 時間
- 30% にした場合：98 + 29 = 127 時間
- 間を取って **25%（123 時間）** とした
