# ユーザーストーリー（練習）：チーム業務共有ボード

> 練習課題2。ヒアリングシート（`hearingsheet-practice.md`）と同じ題材（架空の株式会社サンプル物産 営業推進部）で、
> 「チーム業務共有ボード」の主要機能をユーザーストーリーで書いたもの。
> 各ストーリーは INVEST の6つの条件を満たすように書き、最後に条件ごとのチェック結果をまとめた。
> 機能の ID（F-xx）は要件定義書（`docs/requirements.md`）の機能一覧と対応している。

## 書き方

### テンプレート

```
【誰が】として、
【何を】したい、
なぜなら【なぜ】だから。
```

### INVEST（よいユーザーストーリーの条件）

| 条件 | 意味 | このドキュメントでの書き方 |
|---|---|---|
| **I**ndependent（独立している） | 他のストーリーに依存しない | 1つのストーリーだけで作って動かせる単位にする。依存がある場合は明記する |
| **N**egotiable（交渉可能） | 詳細は後で調整できる | 「何を・なぜ」だけを決め、画面の作りや細かい仕様は「調整できる点」として残す |
| **V**aluable（価値がある） | ユーザーに価値を提供 | 「なぜなら」に、ヒアリングで聞いた困りごと（業務の偏り・期限切れ・相談が流れる）の解決を書く |
| **E**stimable（見積もり可能） | 工数が見積もれる | 各ストーリーに見積もり（ストーリーポイント：1・2・3・5・8）を付ける |
| **S**mall（小さい） | 1スプリントで完了できる | 1スプリント＝1週間とし、5ポイント以下にする。大きいものは分割する |
| **T**estable（テスト可能） | 完了基準が明確 | 「受け入れ条件」を、テストで確かめられる具体的な数字や動きで書く |

### 登場するユーザー

| ユーザー種別 | 説明 |
|---|---|
| 未登録ユーザー | アプリを使う前の営業推進部のメンバー。会員登録・ログイン画面だけ見られる |
| 会員ユーザー | ログインしたチームのメンバー。業務の投稿・閲覧・コメント・ブックマークができる |
| 投稿者 | 業務を投稿した会員ユーザー。自分の投稿だけ編集・削除できる |

## 1. 会員登録・認証

### US-01 会員登録（F-01／Must／3ポイント）
【未登録ユーザー】として、
【メールアドレスと所属チームを入力して会員登録】したい、
なぜなら【自分のチームの業務一覧を見られるようになりたい】だから。

- 受け入れ条件
  - 名前・メールアドレス・パスワード・所属チームを入力して登録できる
  - 所属チームは「第1営業」「第2営業」「営業事務」から1つ選ぶ（Seeder で登録済み）
  - 同じメールアドレスでは登録できない
  - 登録後は自動でログインし、チームの業務一覧に移動する
- 調整できる点：チームを登録後に変更できるようにするか

### US-02 ログイン・ログアウト（F-02／Must／1ポイント）
【会員ユーザー】として、
【ログイン・ログアウト】したい、
なぜなら【取引先の名前が入ったチームの情報を、社外の人に見られないようにしたい】だから。

- 受け入れ条件
  - メールアドレスとパスワードでログインできる。間違っているときはエラーメッセージを表示する
  - ログインしていない状態で業務のページを開くと、ログイン画面に移動する
  - ログアウトするとトップページに戻る
- 調整できる点：「ログインしたままにする」を付けるか

### US-03 パスワードリセット（F-03／Must／1ポイント）
【会員ユーザー】として、
【パスワードを忘れたときに自分で再設定】したい、
なぜなら【ログインできなくなっても、誰かに頼まずに元に戻したい】だから。

- 受け入れ条件
  - 登録したメールアドレスに、再設定用のリンクが届く
  - リンクから新しいパスワードを設定すると、そのパスワードでログインできる
- 調整できる点：リンクの有効期限（初期値 60分）

## 2. 業務の投稿

### US-04 業務の投稿（F-04／Must／3ポイント）
【会員ユーザー】として、
【自分の業務をタイトル・説明・期限・進み具合つきで投稿】したい、
なぜなら【今抱えている仕事をチームに共有して、仕事の偏りに気づいてもらいたい】だから。

- 受け入れ条件
  - タイトル（必須・100文字まで）・説明（任意）・期限（必須）・ステータス（未着手／進行中／完了）を入力して投稿できる
  - 入力に誤りがあると、項目ごとに日本語のエラーメッセージを表示する
  - 投稿すると業務の詳細画面に移動し、「投稿しました」と表示される
- 調整できる点：説明の文字数上限、期限に過去の日付を入れられるか

### US-05 画像の添付（F-09／Must／3ポイント）
【会員ユーザー】として、
【業務に画像を1枚添付】したい、
なぜなら【見積書の画面や名刺の写真で、状況を分かりやすく伝えたい】だから。

- 受け入れ条件
  - 投稿・編集の画面で、画像を1枚選んで添付できる
  - jpg / png / webp で 2MB までの画像だけ受け付け、それ以外はエラーメッセージを表示する
  - 添付した画像が業務の詳細画面に表示される
- 調整できる点：画像の枚数、2MB を超えるスマホの写真の扱い（ヒアリングの確認事項）

> **分割について（Small）**：最初は「画像つきで業務を投稿する」を1つのストーリーにしていたが、見積もりが6ポイントになったため、
> US-04「業務の投稿」と US-05「画像の添付」に分けた。画像なしでも投稿できるので、US-04 だけでも価値がある。

## 3. 閲覧・検索

### US-06 チームの業務一覧（F-05／Must／3ポイント）
【会員ユーザー】として、
【チーム全員の業務を一覧で見】たい、
なぜなら【会議で読み上げなくても、誰がどの仕事をしているのかを一目で把握したい】だから。

- 受け入れ条件
  - 自分が所属するチームのメンバーの業務だけが表示される（他のチームの業務は表示されない）
  - タイトル・担当者・期限・ステータスが、期限の近い順に表示される
  - 1ページ20件で、ページを切り替えられる
- 調整できる点：並び順（期限順・新着順）、他のチームの業務も見られるようにするか（ヒアリングの確認事項）

### US-07 自分の業務一覧（F-06／Must／2ポイント）
【会員ユーザー】として、
【自分の業務だけを一覧で見】たい、
なぜなら【自分がやるべき仕事を整理して、手が回っていない仕事に気づきたい】だから。

- 受け入れ条件
  - 自分が投稿した業務だけが表示される
  - 表示の項目・並び順・ページネーションはチームの業務一覧と同じ
- 調整できる点：完了した業務を隠すボタンを付けるか

### US-08 業務の詳細（F-07／Must／2ポイント）
【会員ユーザー】として、
【業務の内容・画像・担当者・期限を詳しく見】たい、
なぜなら【相談される前に、業務の状況を自分で確かめたい】だから。

- 受け入れ条件
  - タイトル・説明・画像・担当者・期限・ステータス・投稿日が表示される
  - 存在しない業務の URL を開くと 404 になる
- 調整できる点：更新日時（最後に誰がいつ変えたか）を表示するか

### US-09 期限による色分け（F-13／Must／2ポイント）
【会員ユーザー】として、
【期限が近い業務や期限切れの業務を、色とマークで見分け】たい、
なぜなら【期限切れに気づかず、取引先に迷惑をかけることをなくしたい】だから。

- 受け入れ条件（一覧・詳細の両方）
  - 未完了で期限を過ぎている → 赤色の文字 ＋ ⚠
  - 未完了で期限まで0〜3日 → オレンジ色の文字 ＋ ⏰
  - 期限まで4日以上 → 通常の文字色
  - ステータスが「完了」 → 期限に関係なく灰色の文字 ＋ ✓
- 調整できる点：「期限間近」を何日前からにするか（ヒアリングでは3日）

### US-10 キーワード検索（F-11／Must／2ポイント）
【会員ユーザー】として、
【取引先の名前などのキーワードで業務を検索】したい、
なぜなら【たくさんの業務の中から目的のものをすぐ見つけたい】だから。

- 受け入れ条件
  - タイトルと説明にキーワードが含まれる業務が表示される（部分一致）
  - 該当する業務がないときは「該当する業務がありません」と表示される
  - 検索結果でも、自分のチームの業務だけが表示される
- 調整できる点：担当者の名前でも検索できるようにするか

### US-11 期限・ステータスでの絞り込み（F-12／Should／3ポイント）
【会員ユーザー】として、
【期限切れ・期限間近・ステータスで業務を絞り込み】たい、
なぜなら【会議で、問題のある業務だけを話し合いたい】だから。

- 受け入れ条件
  - 「期限切れ」「期限間近（3日以内）」「未着手」「進行中」「完了」で絞り込める
  - キーワード検索と組み合わせられる
- 調整できる点：担当者での絞り込みを追加するか

## 4. コメント・ブックマーク

### US-12 コメント（F-10／Should／3ポイント）
【会員ユーザー】として、
【他のメンバーの業務にコメント】したい、
なぜなら【業務についての質問や相談を、チャットに流さずにその業務に残したい】だから。

- 受け入れ条件
  - 業務の詳細画面で、コメント（必須・500文字まで）を書き込める
  - コメントは投稿者名・日時つきで古い順に表示される
  - 空のコメントは投稿できない
- 調整できる点：コメントが付いたことを投稿者に知らせるか（今回は範囲外）

### US-13 ブックマークの登録・解除（F-14／Must／3ポイント）
【会員ユーザー】として、
【気になる業務を、ページを再読み込みせずにブックマーク】したい、
なぜなら【部下の大事な案件の進み具合を、あとですぐ確認したい】だから。

- 受け入れ条件
  - 一覧・詳細のブックマークボタンを押すと、再読み込みせずに登録・解除が切り替わる（Ajax・CSRF トークンつき）
  - 同じ業務を二重に登録できない
  - 画面を再読み込みしても、登録した状態が残っている
- 調整できる点：ボタンの形（☆・しおりのアイコン）

### US-14 ブックマーク一覧（F-16／Should／2ポイント）
【会員ユーザー】として、
【ブックマークした業務を一覧で見】たい、
なぜなら【気にしている業務だけをまとめて確認したい】だから。

- 受け入れ条件
  - 自分がブックマークした業務だけが表示される（他の人のブックマークは見えない）
  - 一覧から業務の詳細に移動できる
- 調整できる点：並び順（ブックマークした順・期限順）

## 5. 投稿者の機能・権限

### US-15 自分の業務の編集・削除（F-08／Must／3ポイント）
【投稿者】として、
【自分の業務を編集・削除】したい、
なぜなら【進み具合や期限が変わったときに、内容を最新にしたい】だから。

- 受け入れ条件
  - 自分の業務の詳細画面に「編集」「削除」ボタンが表示される
  - 編集すると詳細画面に戻り、「更新しました」と表示される
  - 削除するときは確認ダイアログを表示し、削除後は自分の業務一覧に戻る
- 調整できる点：削除した業務をあとで戻せるようにするか（ヒアリングの確認事項）

### US-16 他人に編集・削除されない（F-15／Must／2ポイント）
【投稿者】として、
【他の人に自分の業務を編集・削除されないように】したい、
なぜなら【自分の業務の情報を勝手に変えられたくない】だから。

- 受け入れ条件
  - 投稿者以外には「編集」「削除」ボタンを表示しない
  - 投稿者以外が編集画面の URL を開いたり、更新・削除を送ったりすると 403 エラーになる（TaskPolicy）
- 調整できる点：チームリーダーには編集を許可するか

### US-17 ステータスをその場で変更（F-17／Could／3ポイント）
【投稿者】として、
【一覧画面で、自分の業務のステータスをその場で切り替え】たい、
なぜなら【編集画面を開かずに、進み具合をすぐ更新したい】だから。

- 受け入れ条件
  - 一覧で「未着手／進行中／完了」を選ぶと、再読み込みせずに更新される（Ajax）
  - 他の人の業務のステータスは変更できない（403）
- 調整できる点：完了にしたときに一覧から消すか

### US-18 自分のコメントの削除（F-18／Could／1ポイント）
【会員ユーザー】として、
【自分が書いたコメントを削除】したい、
なぜなら【書き間違えたコメントを残したくない】だから。

- 受け入れ条件
  - 自分のコメントにだけ「削除」ボタンが表示される
  - 他の人のコメントは削除できない（403）
- 調整できる点：コメントの編集もできるようにするか

### US-19 画像を速く表示（F-19／Could／5ポイント）
【会員ユーザー】として、
【外出先のスマホでも、添付された画像をすぐに表示】したい、
なぜなら【移動中に業務の状況を確認したい】だから。

- 受け入れ条件
  - 画像の保存先を S3 にし、CloudFront 経由で配信する
  - 画像の URL が `https://（CloudFront のドメイン）/...` になっている
- 調整できる点：画像を WebP に変換・縮小するか

| US-05 | 画像の添付 | Must | △ ※1 | ✓ | ✓ | 3 | ✓ ※2 | ✓ |
| US-06 | チームの業務一覧 | Must | ✓ | ✓ | ✓ | 3 | ✓ | ✓ |

| US-11 | 絞り込み | Should | ✓ | ✓ | ✓ | 3 | ✓ | ✓ |
| US-12 | コメント | Should | △ ※1 | ✓ | ✓ | 3 | ✓ | ✓ |
| US-13 | ブックマーク登録・解除 | Must | ✓ | ✓ | ✓ | 3 | ✓ | ✓ |
| US-14 | ブックマーク一覧 | Should | △ ※1 | ✓ | ✓ | 2 | ✓ | ✓ |
| US-15 | 業務の編集・削除 | Must | ✓ | ✓ | ✓ | 3 | ✓ | ✓ |
| US-16 | 他人に編集・削除されない | Must | △ ※1 | ✓ | ✓ | 2 | ✓ | ✓ |
| US-17 | ステータスをその場で変更 | Could | ✓ | ✓ | ✓ | 3 | ✓ | ✓ |
| US-18 | 自分のコメントの削除 | Could | △ ※1 | ✓ | ✓ | 1 | ✓ | ✓ |
| US-19 | 画像を速く表示 | Could | △ ※1 | ✓ | ✓ | 5 | ✓ | ✓ |

- **※1 独立性（I）について**：画像の添付（US-05・US-19）は業務の投稿、ブックマーク一覧（US-14）はブックマークの登録、
  コメントの削除（US-18）はコメント、権限（US-16）は編集・削除の機能があることが前提になる。
  業務やコメントのテスト用データ（Factory・Seeder）を用意すれば、そのストーリーだけで作ってテストできるようにする
- **※2 小ささ（S）について**：「画像つきで投稿」を「投稿」と「画像の添付」に分けたことで、どちらも3ポイントになった
- 色分け・検索・ブックマークは業務一覧（US-06）の画面に付け足す機能なので、作る順番は
  「認証 → 投稿 → 一覧・詳細 → 色分け・検索 → 編集・削除・権限 → ブックマーク → コメント」とする

## 優先度とスケジュール

| 優先度 | ストーリー | ポイント |
|---|---|---|
| Must（必ず作る） | US-01〜US-10、US-13、US-15、US-16 | 30 |
| Should（できれば作る） | US-11 絞り込み／US-12 コメント／US-14 ブックマーク一覧 | 8 |
| Could（余裕があれば） | US-17 ステータス変更／US-18 コメント削除／US-19 画像の配信 | 9 |
| 合計 | | 47 |

1スプリント（1週間）で約15ポイント進められるとすると、ヒアリングで決まった納期（3週間）の中で

| スプリント | 内容 | ポイント |
|---|---|---|
| 1週目 | 認証（US-01〜03）、業務の投稿・画像（US-04・05）、チームの業務一覧・詳細（US-06・08） | 16 |
| 2週目 | 自分の業務一覧（US-07）、色分け・検索（US-09・10）、ブックマーク（US-13）、編集・削除・権限（US-15・16） | 14 |
| 3週目 | 絞り込み（US-11）、コメント（US-12）、ブックマーク一覧（US-14）、Could（US-17〜19）、テスト・修正 | 17 |

Must（30ポイント）は2週目までに終わり、3週目で Should と Could に取りかかれる。

## 書いてみて気をつけたこと
- **「なぜ」はヒアリングで聞いた困りごとから書いた**：「仕事が偏る」「期限切れで迷惑をかけた」「チャットで相談が流れる」など、クライアントの言葉をもとにした（Valuable）
- **受け入れ条件は数字や動きで書いた**：「3日以内はオレンジ＋⏰」「1ページ20件」「他の人が開くと403」のように、テストで確かめられる形にした（Testable）
- **大きすぎるストーリーは分けた**：「画像つきで投稿」を2つに分けて、どちらも1スプリントに収まる大きさにした（Small・Estimable）
- **決めきれないことは「調整できる点」に残した**：他チームの業務を見られるか、削除を戻せるかなど、ヒアリングの確認事項はここに書いた（Negotiable）
