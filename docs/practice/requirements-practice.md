# 要件整理（練習）：曖昧な要求を明確な要件にする

> 練習課題3。チーム業務共有ボードのヒアリング（`hearingsheet-practice.md`）でクライアントから出た「曖昧な要求」を、
> 開発・テストできる「明確な要件」に整理したもの。結果は要件定義書（`docs/requirements.md`）に反映している。

## 整理のしかた

曖昧な要求は、次の5つの手順で明確にした。

| 手順 | やること | 例 |
|---|---|---|
| 1. 何が曖昧かを見つける | 「速く」「使いやすく」「ちゃんと」など、人によって受け取り方が違う言葉を探す | 「速く」→ 何秒なら速い？ |
| 2. 本当の目的を聞く | 「なぜそうしたいのか」を確認し、要求の裏にある困りごとをつかむ | 「目立たせたい」→ 期限切れに気づかず迷惑をかけたから |
| 3. 5W1H で具体化する | 誰が・何を・いつ・どこで・どのように、を決める | 「誰が」編集できる？ → 投稿した本人だけ |
| 4. 数字・条件にする | テストで「できた／できていない」を判断できる形にする | 「近い」→ 期限まで3日以内 |
| 5. 範囲外を決める | 今回やらないことをはっきり書き、あとで揉めないようにする | メール通知は今回はやらない |

## 整理した要求・要件の一覧

| No | クライアントの要求（曖昧） | 何が曖昧か | 確認した質問 | 整理後の要件（明確） | 種別 | 優先度 |
|---|---|---|---|---|---|---|
| R-01 | 期限が近い仕事を目立たせてほしい | 「近い」が何日か、「目立つ」がどういう表示か | 何日前から目立たせたいですか？完了した業務も目立たせますか？ | 未完了で期限まで3日以内は「オレンジ＋⏰」、期限切れは「赤＋⚠」、完了は「灰色＋✓」で表示する | 機能 | Must |
| R-02 | 画面を速く表示してほしい | 「速い」の基準がない | 何秒以内なら待たされたと感じませんか？何件くらい表示しますか？ | 各ページを5秒以内に表示する。一覧は1ページ20件のページネーションにし、Eager Loading で N+1 を防ぐ | 非機能（性能） | Must |
| R-03 | セキュリティをしっかりしてほしい | 何を・誰から守るのかが分からない | 誰に見られると困りますか？他の人に書き換えられても困りますか？ | ログインしていない人は全ページ見られない（auth）。投稿者以外の編集・削除は 403（Policy）。通信は HTTPS。パスワードは bcrypt で保存 | 非機能（セキュリティ） | Must |
| R-04 | 使いやすくしてほしい | 「使いやすい」が人によって違う | 今の Excel で一番面倒な操作は何ですか？ | 入力エラーは項目ごとに日本語で表示。投稿・編集・削除後に完了メッセージを表示。削除前に確認ダイアログを出す | 非機能（使いやすさ） | Must |
| R-05 | スマホでも見られるようにしたい | 見るだけか、投稿もするのか。対応する端末は？ | 外出先で何をしますか？使っているスマホの種類は？ | スマホ・タブレット・PC で崩れずに表示し、すべての操作ができる（レスポンシブ）。対応ブラウザは Chrome・Safari・Edge の最新版 | 非機能（互換性） | Must |
| R-06 | 仕事をすぐ探せるようにしてほしい | 何で探すのか（名前？日付？担当者？） | 探すとき、何を手がかりにしていますか？ | タイトルと説明をキーワードで部分一致検索できる。期限切れ・期限間近・ステータスで絞り込める（検索と組み合わせ可） | 機能 | 検索 Must／絞り込み Should |
| R-07 | 写真も載せたい | 何枚か、どの形式か、大きさの上限 | どんな画像を載せますか？1件に何枚くらい？ | 1件につき画像1枚。jpg / png / webp、2MB まで。それ以外はエラーメッセージを表示する | 機能 | Must |
| R-08 | 仕事のことを相談できるようにしたい | どこで・誰と相談するのか | 今は相談をどこでしていますか？何に困っていますか？ | 業務の詳細画面に、ログインした会員がコメントを書き込める。コメントは古い順に表示する | 機能 | Should |
| R-09 | 大事な仕事をすぐ開けるようにしたい | 「大事」を誰が決めるのか、どこから開くのか | 誰の、どんな業務をすぐ開きたいですか？ | 各会員が業務をブックマークでき（ページの再読み込みなしで登録・解除）、ブックマーク一覧から開ける | 機能 | 登録 Must／一覧 Should |
| R-10 | 止まらないようにしてほしい | いつ・どのくらい止まってはいけないか | 使えないと困る時間帯はいつですか？ | 稼働率 99% 以上を目標とする（平日 9時〜19時を重視） | 非機能（可用性） | Should |
| R-11 | 期限を過ぎたら教えてほしい | 画面で分かればよいのか、メール等で知らせるのか | 画面の色分けだけで足りますか？メールも必要ですか？ | 今回は画面での色分け（R-01）で対応する。メール・チャットへの通知は**範囲外**（発展課題） | 機能 | 範囲外 |
| R-12 | みんなが使えるようにしたい | 「みんな」の範囲（部署内？全社？） | まず誰が使いますか？他部署にも広げますか？ | 対象は営業推進部の3チーム（約30名）。会員登録時にチームを1つ選ぶ。他部署への展開・複数チーム所属は**範囲外** | 制約 | ― |

## ビフォー・アフターの例（詳しく）

### 例1：「期限が近い仕事を目立たせてほしい」（R-01）

**整理前**
> 期限が近い仕事を目立たせてほしい

**曖昧な点**
- 「近い」とは何日前からか？（1日前？1週間前？）
- 「目立たせる」とは？（色？マーク？並び順？）
- 完了した業務も目立たせるのか？

**確認した結果**
- 3日前くらいから気づきたい
- 期限切れは赤にしたい（一番まずいので）
- 完了した業務は目立たなくてよい

**整理後の要件**

| 状態 | 条件 | 表示 |
|---|---|---|
| 期限切れ | 期限の日付を過ぎていて、ステータスが「完了」以外 | 赤色の文字 ＋ ⚠ マーク |
| 期限間近 | 期限まで0〜3日で、ステータスが「完了」以外 | オレンジ色の文字 ＋ ⏰ マーク |
| 通常 | 期限まで4日以上 | 通常の文字色 |
| 完了 | ステータスが「完了」 | 灰色の文字 ＋ ✓ マーク（期限に関係なく） |

**テストで確かめること**（境界値）
- 期限が「今日から3日後」→ 期限間近、「4日後」→ 通常
- 期限が「今日」→ 期限間近、「昨日」→ 期限切れ
- 期限切れでも、完了なら灰色＋✓

### 例2：「セキュリティをしっかりしてほしい」（R-03）

**整理前**
> 取引先の名前が入るので、セキュリティをしっかりしてほしい

**本当の目的**（聞き取り）
- 社外の人に見られたくない
- 同じ部署でも、他人に自分の業務を勝手に書き換えられたくない

**整理後の要件**

| 守るもの | 要件 | 確かめ方 |
|---|---|---|
| 社外の人に見られない | ログインしていない人が業務のページを開くと、ログイン画面に移動する | 未ログインで `/tasks` を開くとログイン画面にリダイレクトされる |
| 他人に書き換えられない | 投稿者以外が編集・削除しようとすると 403 エラーにする。編集・削除ボタンも表示しない | 他のユーザーで `/tasks/{id}/edit` を開くと 403 |
| 通信の盗み見 | 公開環境は HTTPS で通信する | `http://` で開くと `https://` に移動する |
| パスワードの漏えい | パスワードはハッシュ化（bcrypt）して保存する | DB のパスワード欄が平文でない |
| 入力による攻撃 | 出力は Blade の `{{ }}` でエスケープ、フォームと Ajax に CSRF トークン、SQL は Eloquent で組み立てる | `<script>` を投稿しても実行されない |

## まとめ：整理して分かったこと

- **形容詞（速い・使いやすい・しっかり）は、数字や具体的な動きに置き換える。** 置き換えられないと、完成したかどうかを判断できない
- **「なぜ」を聞くと、本当に必要なものが分かる。** 「目立たせたい」の理由は「期限切れで迷惑をかけた」ことで、色分けだけで十分だと分かった（メール通知は不要になった）
- **やらないことも要件として書く。** 「通知」「他部署への展開」を範囲外と書いておくことで、3週間の納期に収められる
- **要件はテストの形で考えるとはっきりする。** 「3日後は期限間近、4日後は通常」のように境界をはっきり決めておくと、テスト（境界値分析）にそのまま使える
