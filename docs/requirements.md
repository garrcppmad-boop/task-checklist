# 要件定義書：チーム業務共有ボード

> **ステータス：初版**（Week 18 作成。Week 21 で見直して確定する）

## 1. プロジェクト概要

### 1-1. アプリの目的
登録したメンバーだけが見られる、メンバーそれぞれの業務をリストにして共有するWebアプリです。
所属しているチーム・部署の中で「誰が・何を・いつまでに」進めているかを共有し、コメントでやりとりできるようにすることを目的とします。

### 1-2. 解決したい課題
- 誰がどの業務を抱えているのかが、チーム内で分からない
- 期限が近い業務や遅れている業務に気づくのが遅れる
- 業務についての確認や相談が、チャットなどに流れて追えなくなる

### 1-3. 想定ユーザー
| ユーザー種別 | 説明 |
|---|---|
| 未登録ユーザー | アプリを使う前の人。会員登録・ログイン画面だけ見られる |
| 会員ユーザー | ログインしたチームのメンバー。業務の投稿・閲覧・コメント・ブックマークができる |
| 投稿者 | 業務を投稿した会員ユーザー。自分の投稿だけ編集・削除できる |

### 1-4. 対象範囲
- チーム（部署）はあらかじめ用意したものから、会員登録のときに1つ選んで所属する
- チームの作成・招待・管理画面は今回の範囲外とする（発展課題）

## 2. ユーザーストーリー

1. 【未登録ユーザー】として、
   【メールアドレスで会員登録】したい、
   なぜなら【チームの業務一覧を見られるようになりたい】から。

2. 【会員ユーザー】として、
   【ログイン・ログアウト】したい、
   なぜなら【チームの情報をメンバー以外に見られないようにしたい】から。

3. 【会員ユーザー】として、
   【パスワードを忘れたときにリセット】したい、
   なぜなら【ログインできなくなっても自分で元に戻したい】から。

4. 【会員ユーザー】として、
   【自分の業務をタイトル・説明・期限つきで投稿】したい、
   なぜなら【今抱えている仕事をチームに共有したい】から。

5. 【会員ユーザー】として、
   【業務に画像を添付】したい、
   なぜなら【資料や画面のスクリーンショットで状況を分かりやすく伝えたい】から。

6. 【会員ユーザー】として、
   【チーム全員の業務を一覧で見】たい、
   なぜなら【誰がどの仕事をしているのかを一目で把握したい】から。

7. 【会員ユーザー】として、
   【自分の業務だけを一覧で見】たい、
   なぜなら【自分がやるべき仕事を整理したい】から。

8. 【会員ユーザー】として、
   【期限が近い業務や期限切れの業務を色やマークで見分け】たい、
   なぜなら【遅れそうな仕事にすぐ気づいて対応したい】から。

9. 【会員ユーザー】として、
   【キーワードで業務を検索】したい、
   なぜなら【たくさんの業務の中から目的のものをすぐ見つけたい】から。

10. 【会員ユーザー】として、
    【他のメンバーの業務にコメント】したい、
    なぜなら【業務についての質問や相談をその場でしたい】から。

11. 【会員ユーザー】として、
    【気になる業務をブックマーク】したい、
    なぜなら【あとで進み具合を確認したい業務をすぐ開きたい】から。

12. 【投稿者】として、
    【自分の投稿を編集・削除】したい、
    なぜなら【進み具合や期限が変わったときに内容を最新にしたい】から。

13. 【投稿者】として、
    【他の人に自分の投稿を編集・削除されないように】したい、
    なぜなら【自分の業務の情報を勝手に変えられたくない】から。

## 3. 機能要件一覧

### 3-1. 必須機能との対応

| 総合プロジェクトの必須機能 | このアプリで当たる機能 |
|---|---|
| ログイン・ログアウト（Breeze） | F-01〜F-03 会員登録・認証 |
| 主要なデータのCRUD | F-04〜F-08 業務の作成・一覧・詳細・編集・削除 |
| 自分のデータだけ編集・削除できる権限管理（Policy） | F-15 投稿者だけが編集・削除できる（TaskPolicy） |
| 検索または絞り込み | F-11 キーワード検索、F-12 期限・ステータスでの絞り込み |
| 画像アップロード | F-09 業務への画像添付（ローカル保存、S3は発展） |
| ページを再読み込みしない操作（Ajax） | F-14 ブックマークの登録・解除 |

### 3-2. 機能一覧

優先度は MoSCoW（Must：必ず作る／Should：できれば作る／Could：余裕があれば作る）で書いています。

| F-09 | 画像アップロード | 投稿に画像を1枚添付できる（jpg / png / webp、2MBまで） | 画像アップロード | Must |

**F-13 の表示ルール**

| 状態 | 条件 | 表示 |
|---|---|---|
| 期限切れ | 期限を過ぎていて、未完了 | 赤色の文字 ＋ ⚠ マーク |

| 通常 | 期限まで4日以上ある | 通常の文字色 |
| 完了 | ステータスが「完了」 | 灰色の文字 ＋ ✓ マーク |

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---|

| F-18 | 自分のコメントの削除 | 自分が書いたコメントだけ削除できる | Could |
| F-19 | 画像のS3保存 | 画像の保存先をS3にして、CloudFront経由で配信する | Could |

### 3-3. 主なデータ

| テーブル | 主な項目 |
|---|---|
| teams | id, name |
| users | id, team_id, name, email, password |
| tasks | id, user_id, title, description, image_path, due_date, status（未着手 / 進行中 / 完了）, created_at, updated_at |
| comments | id, task_id, user_id, body, created_at |
| bookmarks | id, user_id, task_id（user_id と task_id の組み合わせは重複不可） |

**リレーション**
- チーム 1 : N ユーザー
- ユーザー 1 : N 業務
- 業務 1 : N コメント
- ユーザー N : N 業務（ブックマーク）

## 4. 非機能要件

### ■ パフォーマンス
- ページの読み込み時間：5秒以内
- 同時接続数：500ユーザー（目標値）
- 一覧画面はページネーション（1ページ20件）にして、表示件数を抑える
- 一覧で投稿者やコメント数を表示するときは Eager Loading（`with()`）を使い、N+1問題を防ぐ
- アップロード画像は2MBまでに制限する

### ■ セキュリティ
- 通信は HTTPS 化する（公開環境）
- パスワードはハッシュ化して保存する（Laravel 標準の bcrypt）
- XSS 対策：Blade の `{{ }}` で出力をエスケープする
- CSRF 対策：すべてのフォームと Ajax 通信に CSRF トークンをつける
- SQLインジェクション対策：Eloquent・クエリビルダを使い、SQLを直接組み立てない
- ログインしていないユーザーはすべての業務ページを見られないようにする（`auth` ミドルウェア）
- 他のユーザーの投稿の編集・削除は Policy で禁止する
- 画像アップロードは拡張子とサイズをバリデーションする

### ■ 可用性
- 稼働率：99%以上（公開環境での目標値）

### ■ 互換性
- 対応ブラウザ：Chrome、Safari、Edge の最新版
- レスポンシブ対応（スマホ、タブレット、PC）

### ■ 保守性
- ドキュメント整備（README にアプリの説明・環境構築手順を書く）
- コーディング規約準拠（PSR-12、Laravel の命名規則）
- テストコード作成（ログイン、業務のCRUD、Policy による権限チェックの Feature テスト）
- GitHub で機能ごとにコミットし、変更の履歴を残す

### ■ ユーザビリティ
- 入力エラーがあったときは、項目ごとにエラーメッセージを日本語で表示する
- 投稿・編集・削除が終わったら、完了メッセージを表示する
- 削除するときは確認ダイアログを表示する

## 6. 制約条件

### ■ 納期
- 3週間以内

### ■ 技術的制約
- フレームワーク：Laravel（PHP）
- 認証：Laravel Breeze（Blade 版）を使う
- 画面：Blade テンプレートで作る Web アプリとし、ルートは `routes/web.php` に書く
- データベース：MySQL
- 画像の保存先：ローカル（`storage/app/public`、`php artisan storage:link`）。S3 は発展課題とする
- Ajax：JavaScript の `fetch` を使い、CSRF トークンをヘッダーにつけて送る
- バージョン管理：Git / GitHub

### ■ 法律・規制
- 個人情報保護法：メールアドレスなどの個人情報は、アプリの利用目的にだけ使い、適切に管理する
- 著作権：アップロードする画像は、投稿者が権利を持つもの、または使用が許可されたものに限る
- 業務上の機密情報：チームの外に情報が漏れないよう、ログインしたメンバーだけが閲覧できるようにする
- 学習用のアプリのため、実在する会社の機密情報や個人情報はテストデータに使わない

### ■ その他の前提
- チーム（部署）のデータは、Seeder であらかじめ登録しておく
- 1人のユーザーが所属できるチームは1つとする
- レビュー・評価機能は今回は作らない（任意機能のため対象外）
